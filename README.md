# 作业记录本（Homework Tracker）

一个**零构建、单文件**的网页应用：记录课程作业、日程安排和个人探索；支持上传课表截图，在浏览器本地 OCR 识别后生成周课表。

全部逻辑都在一个 `index.html` 里，无 npm、无构建步骤。仓库自带两种用法：

| 模式 | 怎么开 | 数据存在哪 |
|---|---|---|
| **演示模式**（默认） | 直接打开网页 / 双击 `index.html` | 本机浏览器（localStorage） |
| **自建云端版** | 把 `DEMO_MODE` 改成 `false` 并填写自己的后端配置 | 你自己的云端数据库，多设备同步 |

## 🎬 在线演示（点开即用）

**<https://zhangyitian-world.github.io/student-plan-miniapp/>**

不需要注册、不需要联网。演示版把数据存在**你自己浏览器的 localStorage** 里，不上传任何内容；
换设备或清除网站数据就会重置，页面右上角「重置演示」可随时恢复初始示例数据。

## 使用指南

### 1. 先试玩（零配置）

打开上面的演示链接就能用，里面已经预置了一套示例数据，方便看清每个页面长什么样。

### 2. 四个页面

| 页面 | 用途 |
|---|---|
| **课程作业** | 按课程记作业：内容、截止日期/时间、状态、备注。逾期 / 今天 / 明天 / 本周自动标色，三天内截止会置顶提醒 |
| **日程** | 讲座、活动、班会等：分类、名称、日期、开始时间、地点、备注；日期未定的单独分组 |
| **我的探索** | 自己想搞明白的方向（技术、书、工具…），与作业互不干扰 |
| **我的课表** | 周课表网格 + 教学周自动跟随 |

### 3. 课表怎么来

**方式一：截图上交（推荐）**

1. 进「我的课表」→ 右上角 **导入课程详情**；
2. **每张截图放一门课的完整详情**（课名、地点、教师、课程号、星期、节次、周次），可一次多选；
3. 点 **识别待处理截图** —— OCR 完全在你的浏览器里跑，图片不会上传；
4. 逐项**人工校正**（识别结果一律需要核对，缺失信息不会被编造），必要时「＋ 添加一节课程」；
5. 选「合并到现有课表」，点 **确认并保存**。

> 备用：整周课表网格截图可选「整周课表网格（备用）」模式，先对齐网格再识别。非规则排版、无色表格、模糊截图只能尽力提取。

**方式二：手动录入**

「我的课表」→ **校正课表** →「＋ 添加一节课程」，逐门填写星期、节次、周次（格式 `8`、`5-16`、`1-17单`、`2-18双`、`1-4,8,10-12`）。

**让课表知道今天是第几周**

第一次用：点 **设置本周** → 日期默认今天，填上今天对应的教学周 →「保存并回到本周」。
之后应用会按周一自动推进；想查别的周，在顶部切周次即可。

**课程会自动同步到「课程作业」**

课表保存后，里面出现过的课程名会自动进入「课程作业」的课程候选和筛选按钮 —— 不用再手打一遍。

### 4. 想要多设备同步？换成自建云端版

演示模式只能单机使用。要让手机和电脑看到同一份数据，按下面四步换成云端版：

1. **准备后端**：在 [WorkBuddy 云服务](https://www.workbuddy.cn/docs/workbuddy/Overview) 创建一个应用（含 Postgres 与邮箱账号体系）。
2. **建表**：用云端 SQL 工具执行 `timetable-migration.sql`、`events-migration.sql`（迁移工具一次只接受一条语句，按分号拆分逐条执行）。
3. **填配置**：打开 `index.html`，把 `DEMO_MODE` 改成 `false`，并填写自己的配置：
   ```js
   const DEMO_MODE = false;
   const publicConfig = {
     endpoint: "https://你的应用域名",
     publishableKey: "你的 publishable key",
   };
   ```
4. **部署**：整目录上传到任意静态托管（`ocr/` 必须一起部署，否则「截图导入」会失败）。
   注意：云服务的登录/数据接口只在**它注册过的那个发布域名**下可用，所以自建云端版不要放在 GitHub Pages 上跑。

## 功能

- **课程作业**：按课程记录作业，截止日期/时间，到期自动分组标色（已逾期 / 今天 / 明天 / 本周），三天内截止提醒
- **日程**：独立栏目，含活动分类、名称、日期、开始时间、地点、备注；日期未定的单独分组
- **我的探索**：记录自己想搞明白的方向（技术、书、工具…），与作业互不干扰
- **我的课表**：逐门上传课程详情截图（支持多选）→ 浏览器本地 OCR → 校正名称、地点、教师、课程号、星期、节次、周次 → 合并保存为周课表；也支持手动补课及备用网格识别
- **自动教学周**：设置一次某日期对应的教学周，随后按周一自动递增；打开或切回网页默认本周，可手动查看其他周次，设置跟随账号同步
- **其它**：搜索、状态筛选、统计卡、PWA「添加到主屏幕」、多设备自动刷新

## 技术特点

- **单文件应用**：全部逻辑内联在 `index.html`，双击即可打开，无需 npm、无构建步骤
- **双后端**：演示模式用 localStorage；云端模式经 CDN 加载云 SDK（带三级镜像回退 jsdelivr → fastly → unpkg）
- **OCR 全部本地执行**：Tesseract.js 静态托管在同源目录 `ocr/`，截图不上传、不入库
- **原生 JS + 原生 CSS**，无框架、无依赖树

## 目录结构

```
index.html                 # 全部应用逻辑（HTML + CSS + JS 内联，含演示模式后端）
manifest.json              # PWA 清单
icon-180.png / icon-512.png# 主屏幕图标
timetable-migration.sql    # 课表表结构 + RLS
events-migration.sql       # 日程字段（homework.location）
ocr/                       # Tesseract.js 7.0.0 静态组件、WASM 与中英文模型
.nojekyll                  # GitHub Pages：跳过 Jekyll
```

## 隐私与安全

- **演示模式不发送任何数据**：所有记录只写入本机浏览器的 localStorage
- **云端模式**：每张表都开启 **RLS**，策略为 `owner_id = auth.uid()`，登录用户只能读写自己的记录
- 前端**从不传 `owner_id`**，由数据库默认值 `auth.uid()` 填充
- `publishableKey` 是**客户端公开密钥**（设计上就写在页面里），不是服务端密钥；但仓库里仍建议用占位符，避免把具体实例地址公开

## 第三方组件

`ocr/` 下为官方 Tesseract.js 7.0.0 静态文件与 `4.0.0_best_int` 中英文模型，许可证随目录保留（`ocr/LICENSE.md`、`ocr/core/LICENSE`）。界面图标来自 lucide-static（ISC 许可），许可声明保留在 `index.html` 内联 SVG 注释中。

## 说明

默认每张截图包含一门课的完整详情；图片大小和边距无需一致，可自动尝试定位详情区域，或手动调整识别范围。连续上传、多图顺序识别、失败重试均保留已识别结果。原图不上传，缺失信息不会补造；识别结果一律需要人工校正并确认。

默认提供 12 节起止时间，可按实际课时修改；每门课的钟点时间由开始、结束节次映射得出。一门课有多段上课安排时分别确认，单双周、散周和缺失周次需特别核对。未填写学期或必需的排课信息时不能保存。备用网格识别只能尝试处理规则周课表。
